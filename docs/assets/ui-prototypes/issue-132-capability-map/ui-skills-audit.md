# Issue #132 · 阶段 1 修订版高保真交互原型 UI 专业 Skills 审查（阶段 2 评审包）

## 设计方向

- **视觉主张：** 保留当前 TCP 克制、浅色、企业工具式能力地图；唯一强化点是用同一条蓝色选择语言贯穿 L1 Tab、L2 分组和 L3 目标，让页面选择与地址栏状态形成连续路径。
- **内容计划：** TCP shell → 标题、搜索与角色对应操作 → sticky 六域导航 → L1 概述 → L2/P4–P8 → L3 查看 Drawer；Leader 另有独立维护 Drawer。
- **交互主张：** URL 的 `role=member|leader` 是评审状态而非伪造切换；Hash 仍只表达能力路径；浏览器历史、搜索键盘、sticky 焦点偏移、关闭/取消焦点恢复与 reduced motion 均保持可操作。
- **视觉来源：** 直接复用仓库当前能力地图 1440×900 / 1920×1080 视觉基线和 `docs/04_UI.md`，因此没有另造三套风格候选，也没有生成装饰图片。

## 审查中发现并修正

1. **P2 · 原型曾在页面内重复显示“当前路径”。** 地址栏已承担该职责，额外标签偏离现有视觉基线；已删除，避免提示文案泄漏进产品界面。
2. **P2 · 默认 P01/P02 列表最初只有部分 L2。** 虽足够演示，但与正式信息密度不一致；已补齐 P01 十组和 P02 十组，其中 P02.07–P02.10 保留明确空路径语义。
3. **P3 · 全页截图曾出现跳转链接拼接伪影。** 将 skip link 的隐藏方式改为负 `top`，键盘聚焦时仍可见，浏览器证据中不再产生伪影。
4. **移动操作密度。** 搜索、清除、工具按钮和 Drawer 关闭按钮在窄视口统一达到至少 44px；桌面 Web 仍保持紧凑。
5. **Stage-2 导航与表单边界。** 用容器 `scrollLeft` 替代 Tab 的 `scrollIntoView`，避免纵向位置被浏览器重算；表单保持原生 `input`、`select`、`textarea`、checkbox 和 fieldset，不新增依赖。P4–P8 只读矩阵在详情中给出明确维护边界，避免把标准版本编辑误放进 L3 目录表单。
