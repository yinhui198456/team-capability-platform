# TCP Iteration 2：能力目录与学习资源只读设计

## 1. 目标与边界

本迭代交付可追溯的能力目录和学习资源目录，为后续自评、Gap、计划和任务提供只读标准来源。

- 能力目录只包含 MVP 启用的六个一级能力域：P01、P02、P03、C01、C02、C03。
- 能力目录展示 L1 → L2 → L3 层级，L3 是后续评估、计划和跟踪的最小单元。
- 学习资源仅展示材料索引及其与 L3 的关联；它不是课程管理、Evidence 或文件托管。
- 当前开发期没有账号会话；目录数据对匿名访问者只读。认证和角色执行留给后续迭代。

本规格不改变冻结的 `01_Product`、`02_Design`、`03_Data`、`04_UI` 与 `05_Development` 业务规则。

## 2. 固定数据来源

本迭代只接受仓库中以下两个固定工作簿和工作表；不提供浏览器上传、用户选择文件、字段映射或增量合并能力。

| 数据 | 固定文件与工作表 | 使用边界 |
|---|---|---|
| 模型概览与等级描述 | `capability-model/技术架构与开发专业线能力胜任模型20260509_V1.0.xlsx` / `1_能力模型` | 提供模型名称、L1 名称及 P4–P8 描述；不从该表生成 L2/L3。 |
| L1/L2/L3 及 L3 属性 | `capability-model/团队成员年度学习计划模板_基于能力模型_V1.3.xlsx` / `02_能力差距自评` | L3 的唯一导入来源。导入编码、名称、父级、建议起始职级、学习材料原文、预期输出/验收方式、预计耗时和排序。 |
| 学习资源索引 | `capability-model/团队成员年度学习计划模板_基于能力模型_V1.3.xlsx` / `06_学习材料索引` | 导入材料编码、名称、类型、来源/链接、用途和状态。 |

导入器只从模型工作簿读取六个白名单 L1 的概览和等级描述；其中“架构与工程能力”“咨询与方案能力”“DevOps 与稳定性能力”是已知扩展占位，读取时跳过，不是导入错误。除这三个明确占位外，任何出现在 L3 来源表中的未知 L1 都是硬错误。扩展占位不能导入为有效 L1/L2/L3，不能出现在本迭代的 API 或页面可操作数据中。

## 3. 数据基线

成功导入后的目录基线如下：

| L1 | L2 数 | L3 数 |
|---|---:|---:|
| P01 Data Infra 能力 | 10 | 82 |
| P02 AI Infra / Agent 能力 | 6 | 41 |
| P03 Coding 能力 | 9 | 70 |
| C01 基本办公能力 | 7 | 42 |
| C02 沟通协作 | 7 | 35 |
| C03 学习创新 | 8 | 40 |
| 合计 | 47 | 310 |

学习资源索引基线为 95 条唯一材料编码。导入完成后必须能按 L1、L2、L3 编码回溯到固定工作簿的来源行。

## 4. PostgreSQL 目录存储

本迭代只新增以下四张目录表；不创建 Assessment、Gap、Growth Goal、Annual Growth Plan、Plan Item、Learning Task、Evidence、Review、用户或角色表。

| 表 | 最小职责 | 关键约束 |
|---|---|---|
| `capability_model` | 保存单一生效模型的编码、名称、版本、来源工作簿、来源工作表和来源行号 | 模型编码唯一；本迭代仅有一个生效模型。 |
| `capability_node` | 统一保存 L1/L2/L3；字段包含模型、父节点、节点类型、编码、名称、排序、L1 类型/启用标识及 P4–P8 描述、L3 建议起始职级、原始学习材料、预期输出/验收方式、预计耗时、来源工作簿、来源工作表和来源行号 | 同一模型内节点编码唯一；L1 无父节点，L2 的父节点为 L1，L3 的父节点为 L2；只允许白名单六个 L1。 |
| `learning_resource` | 保存材料编码、名称、类型、来源/链接、用途、状态、来源工作簿、来源工作表和来源行号 | 材料编码唯一。 |
| `capability_node_resource` | 保存 L3 与学习资源的多对多关联 | 仅允许 L3 节点关联资源；同一节点和资源的组合唯一。 |

`capability_node.materials_text` 必须保存 Excel 的完整原文。它既是来源追溯字段，也是无法解析为索引资源时的唯一展示依据。

## 5. 宽容导入规则

导入是受控初始化动作，不经由匿名 HTTP 接口触发。它读取固定工作簿，验证后写入四张目录表；任何硬错误均不得留下部分导入结果。

1. 仅导入白名单六个 L1；L3 来源表出现未知 L1、重复节点编码、缺失 L1/L2/L3 必填字段或父级不一致均为硬错误，导入失败并保留旧目录。L3 必填字段为能力类别、L1/L2/L3 的编码和名称、建议起始职级、学习材料原文、预期输出/验收方式、预计耗时。
2. L3 的 `学习材料` 原文始终原样保存为 `materials_text`。
3. 从原文中识别规范材料编码（`Pxx-Mxxx` 或 `Cxx-Mxxx`）。只有编码存在于 `06_学习材料索引` 时，才建立 `capability_node_resource` 关联。
4. 未在索引中命中的引用不创建虚构资源、不替换原文、不丢弃 L3。API 将它们标记为“来源待补充/未关联”。
5. `P02.06.03` 至 `P02.06.07` 的 `A8` 引用，以及带有“内部…模板/规范”等非编码文本的引用，属于第 4 条的宽容数据；它们是可见警告，不是本次导入的硬错误。
6. 资源索引中未被任何 L3 引用的材料仍应导入并可在资源目录查看。

导入报告至少包含：导入的模型数、L1/L2/L3/资源/关联数、未关联原文列表和硬错误列表。报告只供开发与运维核对，不新增页面。

## 6. 只读 API 契约

所有目录 API 仅提供 `GET`；对 `POST`、`PUT`、`PATCH`、`DELETE` 返回方法不允许。响应不包含用户、评估、计划、任务、Evidence 或 Review 数据。

| 路径 | 用途 | 最小响应 |
|---|---|---|
| `GET /api/capability-model` | 返回当前模型、六个 L1、可展开的 L2/L3 和 L1 的 P4–P8 描述 | 模型元数据、节点树、L3 属性、`materials_text`、已关联资源摘要、未关联引用提示。 |
| `GET /api/capability-model?domain_code={code}` | 返回一个白名单 L1 的完整子树 | 与全量模型相同的该域内容；未知或扩展域返回未找到。 |
| `GET /api/learning-resources` | 返回材料索引 | 材料字段、关联 L3 数；支持名称、状态和 L3 编码的只读筛选。 |
| `GET /api/learning-resources/{material_code}` | 返回单个材料及其关联 L3 | 材料字段与关联 L3 编码、名称、所属 L1/L2。 |

`/api/capability-model` 的输出只能包含六个白名单域和其节点。资源详情未找到返回未找到；没有关联 L3 的有效资源仍返回空关联列表。

## 7. 页面与匿名开发期访问

| 路由 | 页面内容 | 开发期访问规则 |
|---|---|---|
| `/capability/model` | L1/L2/L3 树、P4–P8 描述、L3 属性和关联资源摘要 | 匿名只读可访问。 |
| `/operations/resources` | 资源列表、筛选、详情和关联 L3 反查 | 匿名只读可访问。 |

两个页面均不提供编辑按钮、导入按钮、上传控件、删除操作、角色切换或模拟角色。此匿名策略只用于开发期只读目录演示；它不定义将来的 RBAC 行为，也不替代后续内置账号会话。

## 8. 明确排除项

- 在线维护能力模型或学习资源。
- Excel 上传、导出、版本合并、增量导入、用户自定义字段映射。
- 附件托管、资源内容代理下载、课程/学时/讲师/认证生命周期。
- Assessment、Gap、Growth Goal、年度成长计划、Plan Item、Learning Task、Learning Progress Log、Evidence、Buddy Review、成长档案和团队分析。
- 认证、Cookie 会话、用户、角色、权限执行、Buddy 关系和多团队。
- 对 Compose 服务、端口、持久卷拓扑或既有健康检查的改动。唯一例外是：允许将后端镜像的 Compose 构建上下文设为仓库根目录，并继续指定 `backend/Dockerfile`，以便 Dockerfile 复制根目录 `capability-model/*.xlsx` 到后端镜像；不得借此改动任何服务、端口、卷或健康检查。

## 9. 导入错误与验收

### 9.1 错误处理

| 情况 | 结果 |
|---|---|
| 文件或固定工作表不存在 | 硬错误；不写入目录。 |
| L3 来源表出现不在六域白名单的 L1 | 硬错误；不写入目录。模型概览表中的三个已知扩展占位跳过且不报错。 |
| L1/L2/L3 编码重复、缺失或父级不一致 | 硬错误；不写入目录。 |
| 资源编码重复或资源必填字段缺失 | 硬错误；不写入目录。资源必填字段为材料编码、材料名称、材料类型、材料来源/附件名、用途说明和材料状态。 |
| `A8`、内部文本或不存在的规范资源码 | 宽容警告；保留原文，跳过关联，不阻断 310 L3 导入。 |

### 9.2 验收清单

1. 本迭代仅新增本规格定义的四张目录业务表；不新增评估、计划、任务、Evidence、Review、用户或角色业务表。
2. 能力模型 API 与 `/capability/model` 只返回六个有效 L1、47 个 L2、310 个 L3；三扩展域完全不出现。
3. 每个 L3 可显示其编码、名称、父级、建议起始职级、预期输出/验收方式、预计耗时和 Excel 原始学习材料。
4. 学习资源 API 与 `/operations/resources` 返回 95 条唯一材料编码；已匹配的材料可双向追溯到 L3。
5. `A8` 和内部文本在 L3 页面中明确显示为来源待补充/未关联，且不会被伪造为学习资源。
6. 四条 API 只接受读取方法；任何写方法不创建或修改目录数据。
7. 匿名访问可读取两个目录路由和只读 API，但看不到任何评估、Gap、计划、任务、Evidence、Review 或用户数据。
8. `docker compose config` 继续通过；允许后端镜像为复制根目录 `capability-model/*.xlsx` 而将构建上下文改为仓库根目录并指定 `backend/Dockerfile`；现有前端、后端、PostgreSQL 服务名、端口、卷和健康检查不变。
