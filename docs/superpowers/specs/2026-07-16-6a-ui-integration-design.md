# 迭代 6A：Member / Buddy UI 整合设计

## 目标与边界

在用户明确授权 4-5、5-4 UAT 延后后，实施迭代 6A：以既有业务规则和 API 为基础，完成 UI-01 至 UI-04 的 Member / Buddy 视觉与交互整合。

包含：

- UI-01 `我的成长看板`：年度进度、学习时长、待办、六个启用能力域的 Gap、当前学习任务。
- UI-02：能力自评、Gap 与计划门禁的统一工作台视觉。
- UI-03：年度计划、学习任务、Evidence / 日志的统一工作台视觉。
- UI-04：Buddy 成员筛选、自评 / Evidence 队列、反馈工作区与历史的整合。

不包含：UI-05、Leader 或 Admin 页面、业务对象/状态机变更、消息中心、导出、图表库、4-5 或 5-4 的 UAT 通过声明。

## 实现方案

### 工作台壳

为 6A 路由复用一个响应式工作台壳：深蓝顶部导航、角色相关的左侧导航、浅灰蓝内容区和白色卡片。现有页面仍各自负责数据加载和业务操作；壳只负责布局、导航与当前页状态，避免重写已验证的业务逻辑。

### UI-01 数据与呈现

新增一个只读 Member 看板聚合端点。它由现有 Assessment、Annual Growth Plan、Learning Task、Learning Progress Log、Evidence 数据计算：

- 年度计划状态统计和整体进度；
- 全年/当月计划与实际学习时长；
- 待提交 Evidence、待 Buddy Review、到期、延期待办；
- 六个已启用能力域的当前/目标掌握度和 L3 Gap；
- 未完成、待 Review、延期的当前学习任务。

服务端强制只返回当前 Member 本人的数据。前端使用原生 SVG 绘制能力雷达图，并以能力域筛选联动 Gap 列表；不引入图表依赖。

### UI-02 与 UI-03

保留自评、Gap、年度计划和学习任务页面的现有 API 与行为。仅按固定原型重组为表格、状态标签、摘要卡、筛选区和详情区；统一展示已有的 Review 门禁原因、计划状态、学习日志和 Evidence 版本历史。

### UI-04

Buddy 复核中心复用现有待自评复核和待 Evidence Review 查询。页面提供成员筛选与两类队列的 Tab；选中项在同一工作区显示现有依据、历史及反馈提交控件。自评结论仍为“认可/建议调整”，Evidence 结论仍为“通过/需补充/驳回”。

## 测试与验收

每个增量先写失败测试：

1. 后端：看板聚合口径与仅本人可见；
2. UI-01：指标、能力域筛选、Gap/任务跳转；
3. UI-02/03：既有关键操作在新壳内继续可用；
4. UI-04：成员范围、队列 Tab、反馈提交与历史可见性。

完成后运行后端 pytest、Ruff、Black，以及前端 Vitest、ESLint、构建、Prettier 检查。6A 完成后才可将 6A-4 交由用户 UAT；不自动开始 6B。
