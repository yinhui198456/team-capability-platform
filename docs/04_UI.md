# 04 UI

## 1. 文档目标与边界

本文档将 `01_Product`、`02_Design`、`03_Data` 转化为页面规格，作为后续原型开发与验收依据。

- 适用范围：技术架构与开发专业线、单团队、少于 10 人。
- 启用能力域：P01 Data Infra、P02 AI Infra / Agent、P03 Coding、C01 基本办公、C02 沟通协作、C03 学习创新。
- 页面定位：内部 Web 运营工作台；不建设 LMS、绩效评审、独立消息中心、综合总分。
- 角色：Member、Buddy、Leader、Admin；权限与数据范围按有效角色叠加。
- 视觉基线：已确认的 5 张原型图。采用深蓝顶部导航、浅灰蓝工作区、白色卡片、紧凑表格和蓝/绿/橙/红状态标签。

## 3. 通用交互与状态规范

### 3.1 通用组件

| 组件 | 规则 |
|---|---|
| 状态标签 | 未开始/进行中/暂停/延期/已完成/取消（已完成、取消为终态）；用文字加颜色共同表达。「待 Evidence Review」是 Evidence 状态，不是任务状态标签 |
| Evidence 版本 | 显示版本号、提交时间、提交人、Review 结论；历史版本只读，不回流 |
| Review 面板 | 固定显示关联 Member、L3、依据、历史、结论与反馈；结论提交后归入历史 |
| 时间与范围筛选 | 年度、成员、能力域、状态；默认值与角色数据范围一致 |
| 空态 | 明确说明“暂无待办/暂无计划/暂无权限”，给出可执行入口或返回路径 |
| 首页提醒 | 仅在看板展示待提交 Evidence、待复核、计划到期、任务延期；不建设独立消息中心 |

### 3.2 指标口径

| 指标 | 口径 |
|---|---|
| Gap | 服务端确认的最终有效目标 − 当前掌握度；不适用项显示 `—` 且不参与统计 |
| 能力实际值 | 当前掌握度按能力域聚合后的均值 |
| 能力计划值 | 目标掌握度按能力域聚合后的均值 |
| 成员能力达成率 | 当前掌握度 ÷ 目标掌握度 × 100%；目标为 0 时显示 `N/A`；允许大于 100% |
| 年度计划进度 | 计划项按未开始、进行中、已完成、延期、暂停、取消统计 |
| 延期计划项 | 当前日期晚于计划截止日期，且状态不是已完成或取消的计划项 |
| 当月计划完成数 | 目标月份或计划截止日期落在当月的计划项数 |
| 当月实际完成数 | 实际完成日期落在当月且状态为已完成的学习任务数 |
| 累计计划完成率 | 截至当月应完成计划项数 ÷ 年度计划项总数 |
| 累计实际完成率 | 截至当月实际已完成计划项数 ÷ 年度计划项总数 |
| 全年计划时长 | 年度成长计划内计划项预计耗时之和 |
| 全年累计时长 | 年度内学习执行日志实际时长之和 |
| 当月计划时长 | 目标月份落在当月的计划项预计耗时之和 |
| 当月累计时长 | 学习执行日志记录日期落在当月的实际时长之和 |

### 3.3 数据补充要求

学习时长来自 `03_Data` 已定义的 **Learning Progress Log（学习执行日志）**：

- 固定字段为 `task_id`、`record_date`、`actual_hours`、`note`、`recorder`；每条日志关联一个 Learning Task。
- 日志仅用于按 `record_date` 聚合学习时长，不拆分计划项或学习任务，不改变“一计划项对应一学习任务”的 MVP 规则。
- Member 可新增或编辑本人日志；Buddy、Leader 按负责成员 / 团队范围查看；Admin 全量查看。

视觉核对备注：已逐一核对 `docs/assets/ui-prototypes/UI-01..UI-05` 实际 PNG；五张图的布局要素与本节映射一致，未发现需静默假设的视觉差异。学习执行日志不新增独立页面，继续在 UI-01、UI-03 及月度复盘的既有区域呈现。

### 3.4 L2 能力标准与 L3 达成路径

- L2 是正式的“二级能力标准 / 职级要求”，P4–P8 仅表示该 L2 的岗位职级要求。
- L3 是父 L2 的“三级达成路径 / 学习实践项”，其当前、目标和 Gap 均为 1–5 掌握度，不是岗位职级。
- 涉及 Gap、目标、计划、任务、Evidence、资源和团队运营的页面统一显示 **`{l2_code} · {l2_name} → {l3_code} · {l3_name}`**；不能映射当前模型时保留原始 L3 code，名称可为空。
- 成员有目标职级时展示目标职级对应的 L2 要求；否则回退当前职级；两者缺失、非法或该等级文本为空时显示“职级要求暂不可用”，不得默认 P4。
- 已提交、已复核、已归档 Assessment 仅展示当前模型映射上下文和既有 1–5 目标/Gap 快照，不将实时 L2 P4–P8 长文本作为历史事实。

## 4. 关键页面规格

### 4.1 我的成长看板

**页面目标：** Member 快速了解年度计划执行、能力差距、当前学习任务和待办。

**对应视觉原型：** UI-01。验收时重点核对三组布局：计划执行、能力分析、学习执行；不得恢复已取消的能力域覆盖、重点提升建议等模块。

| 区域 | 展示内容 | 操作与联动 |
|---|---|---|
| 年度计划进度 | 整体进度环；计划项、已完成、进行中、未开始、延期数量 | 点击状态进入年度成长计划并带入状态筛选；延期用红/橙标签突出 |
| 学习时长 | 全年累计时长、全年计划时长、当月累计时长、当月计划时长 | 点击进入月度复盘或学习任务；数据来自计划项与学习执行日志 |
| 待办事项 | 待提交 Evidence、待 Buddy 复核、计划到期、学习任务延期 | 点击进入相应列表并自动筛选 |
| 能力分析 | 能力域筛选器、个人能力雷达图、Gap 概览 | 见下方联动规则 |
| 当前学习任务 | L2 能力标准 → L3 达成路径、计划月份、预计/实际时长、进度、状态 | 点击进入学习任务详情；仅显示未完成、待 Review、延期任务 |

**能力雷达图与 Gap 联动：**

1. 默认选择“全部”，雷达图展示六个能力域，Gap 概览展示全部 L3 差距；
2. 点击雷达图某一能力域或顶部能力域筛选项后，Gap 概览仅展示该能力域的 L3；
3. Gap 概览字段：L2 能力标准 → L3 达成路径、当前掌握度、目标掌握度、Gap、优先级；雷达图和领域均值均标注为 L3 掌握度聚合；
4. 提示文字：`选择能力域查看对应 Gap`；
5. 看板仅展示已启用的六个能力域。

**不展示：** 能力域覆盖卡片、重点提升建议、综合总分、独立消息中心。

#### 4.1.1 动态阶段与主按钮

Member 工作台根据当前年度 assessment 与年度计划状态动态展示：

| 阶段 | 触发条件 | 页面主标题 | 主按钮 | 展示内容 | 隐藏内容 |
|---|---|---|---|---|---|
| 待完成自评 | 无年度 assessment，或最新 assessment 为 `草稿` | 完成能力自评 | 开始能力自评 → `/capability/assessment` | 自评引导卡片 | 计划进度、学习时长、待办、雷达/Gap、任务 |
| 待复核 | 最新 assessment 为 `待复核` 或 `建议调整` | 自评已提交 | 查看复核状态 → `/capability/assessment` | 复核状态、Gap 概览 | 计划进度、学习时长、待办、当前任务 |
| 待制定计划 | assessment 已复核/已归档，但年度 plan 尚未创建 | 准备生成年度计划 | 生成年度计划 → `/growth/annual-plan` | 生成年度计划引导 | 计划进度、学习时长、待办、当前任务 |
| 计划执行中 | 年度计划为 `制定中` 或 `执行中` | 我的成长总览 | 查看年度计划 → `/growth/annual-plan` | 年度计划进度、学习时长、待办、雷达/Gap、当前学习任务 | 无 |
| 年度已归档 | 年度计划状态为 `已归档` | 年度成长总结 | 查看成长档案 → `/growth/profile` | 年度总结、成长档案入口 | 待办事项、当前学习任务 |

顶部统一显示：年度、`数据范围：本人`、当前阶段标签。

#### 本周学习节奏（Issue #181）

- 仅在「计划执行中」展示，使用 `dashboard.meta.as_of` 所在周的周一至周日；缺失时才使用浏览器当天。
- 读取本人 Learning Task 的学习日志，排除已作废及周外记录；同日时长相加，并按真实日期升序展示。摘要为「本周学习 N 天 · 共 X 小时」，时长不显示无意义的 `.0`。
- 零记录时只显示「本周暂无学习记录。」；有当前任务时入口为「去学习任务」→ `/growth/annual-plan`，否则为「查看年度成长计划」→ `/growth/annual-plan`。不得展示空图、坐标轴、七天占位或「0小时」。
- 加载时显示「正在加载本周学习记录…」。任一日志请求失败时仅显示「本周学习记录加载失败，请重试。」和「重新加载」；不得展示部分结果，重试只重新读取本周学习数据。
- 不展示打卡、连续学习、落后、积分、排名、周目标或新的 KPI；1440/1024 不得遮挡关键内容，768 宽度下入口可操作。

### 4.2 能力自评与 Gap 分析

> ⚠️ 本页对应原型 M02 能力评级与提升计划 V1：按 Issue #187 故事合同，「保存能力评级」「加入/移出提升计划草稿」「生成所选学习任务」为三个独立动作；提升项持久化为计划草稿；Review 认可门禁已废弃（不创建新的自评复核队列）。下列"Review 认可闭环后才可纳入计划"相关表述仅描述历史语义。

**页面目标：** Member 可增量保存任意已填写的 L3 评级，维护可恢复的提升计划草稿，并仅在显式选择后生成学习任务；三者是独立动作，不创建新的 Assessment Review。计划月份唯一输入为 `YYYY-MM`，季度仅由月份推导。详见 [TCP-194-BL-v1](https://github.com/yinhui198456/team-capability-platform/issues/194#issuecomment-5391052088) 与 [TCP-194-SOL-v1](https://github.com/yinhui198456/team-capability-platform/issues/194#issuecomment-5391595434)。

**对应视觉原型：** UI-02。验收时重点核对 L3 表格层级、Gap 侧栏和“Review 闭环前不可正式纳入计划”的状态提示。

| 区域 | 展示内容 | 操作 |
|---|---|---|
| 评估头部 | 年度、评估版本、自评进度、最新 Review 状态 | 保存草稿、提交自评、查看评估历史 |
| 自评明细表格 | L1/L2/L3 层级；L2 标注“二级能力标准 / 职级要求”，L3 标注“三级达成路径 / 学习实践项”；当前掌握度、只读标准目标、个人调整、最终有效目标、Gap、优先级、自评依据、状态 | 展开/收起、填写 L3 当前掌握度与依据、按能力域筛选；已适用项可申请调整 |
| 自评依据 | 文件/链接、完成场景、备注 | 查看、添加、删除草稿附件 |
| Gap 侧栏 | Gap 总数、均值、高优先级项、分布 | 查看详情、筛选高优先级项 |
| 纳入年度计划 | 最新 Review 认可闭环前显示禁用状态及原因；闭环后可选择 Gap 项纳入计划 | 勾选“是否纳入计划”，进入成长目标/年度成长计划 |

**关键规则：**

- 提交自评后立即生成 Gap，可查看、筛选和设置优先级；
- 标准目标由服务端在 Assessment 创建时生成并只读展示；页面不得提交或覆盖标准目标、最终有效目标；
- 已适用项提供「申请调整」开关、1～5 调整值和必填原因；取消申请时清空调整值与原因；
- 标准目标为「不适用」时，当前行显示不适用状态，禁用个人调整和计划候选，Gap 显示 `—`；
- Buddy 的建议调整不阻塞查看 Gap；
- 正式将 Gap 纳入年度成长计划（包括生成年度成长计划及其计划项）的统一门禁：当前 Assessment 最新一次提交对应的 Assessment Review 已闭环，Review 结论为「认可」，且不存在待复核事项。
- 不显示未来扩展域。
- L2 分组头显示成员目标职级（无目标时当前职级）对应要求，并提供 P4–P8 完整要求入口；无 L3 的 L2 显示“暂无三级达成路径，当前无可评估项”，不计入自评完成率。

#### Issue #50 交互与密度验收

- 正常页面一次只展示一个 L1，不提供常驻「全部能力域」模式；L1 显示已完成数/总数，L2 可折叠且默认只展开当前操作或定位项所在组。
- 全局搜索检索所有 L1；选择结果后切换 L1、展开 L2、滚动并聚焦 L3。定位未完成和提交失败使用同一套路径，支持键盘选择、焦点恢复和集中异常提示。
- 移除固定 260px Gap 右栏；Gap 详情使用默认关闭的 Drawer。关闭时主表使用完整可用宽度，不保留固定统计栏或无效留白。
- 页头和摘要为紧凑单行，说明与未完成提示合并；P4–P8、1–5 说明进入 Tooltip/帮助入口；表头固定；底部吸附操作栏不得遮挡最后一项。
- 主表视觉面积最低占内容区 70%，目标 75%–80%。1440×900 首屏至少 6 条完整能力项，1920×1080 至少 8 条；1280×800 不得页面级横向溢出、遮挡或出现无效大面积留白。

### 4.6 能力地图（Issue #52）

**页面目标：** 在不连续挂载全部能力域和 L3 节点的前提下，浏览 L1 概述、比较 L2 职级要求，并从 L2 进入 L3 达成路径详情。

**搜索与定位：**

- 搜索覆盖 L1、L2、L3 的编号和名称，结果明确标识“能力域”“能力标准”或“达成路径”，并显示编号、名称及所属 L1/L2 上下文。
- 输入过程中只展示结果，不自动跳转；多结果必须由用户选择。选择 L1 切换能力域并聚焦域概览；选择 L2 切换能力域、展开并聚焦对应 L2；选择 L3 切换能力域、展开父 L2 并聚焦对应 L3 行，但不自动打开 Drawer。
- 清除搜索保留当前能力域、L2 折叠状态和已完成的定位；无结果显示明确空态；新搜索结果或新能力域生效前关闭旧 Drawer，避免上下文错配。
- 兼容资源页 `/capability/model#L3_CODE` 反向链接。初始 Hash 命中 L3 时，加载模型后自动切换 L1、展开父 L2 并聚焦 L3 行，不自动打开 Drawer 或编辑表单。

**状态与数据流：**

- `searchQuery` 和派生的 `searchResults` 保存搜索输入与结果；切域、搜索定位、打开/关闭 Drawer 不重新请求能力模型。
- L2 状态返回原能力域时恢复；Drawer 开关不得改变当前域、搜索条件或 L2 状态。

**响应式与密度验收：**

- 1440×900 首屏保持紧凑页头、L1 导航、一级概述和至少 4 个 L2 入口/等量主体内容；不得出现页面级横向滚动、重叠、遮挡或严重文字碎裂。

## 7. 与后续开发的衔接
